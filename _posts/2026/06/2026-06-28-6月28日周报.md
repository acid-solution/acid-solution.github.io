### 每日内容总结

06/22 主要是配置 MySQL 环境，并为 Todo 项目设计 `todos` 表。表里包含 `id`、`title`、`description`、`completed`、`created_at`、`updated_at` 这些字段。这里重新复习了一些 MySQL 的基础类型，比如 `BIGINT`、`VARCHAR`、`BOOLEAN`、`DATETIME`，也理解了为什么后端表通常都需要主键，以及 `created_at` 和 `updated_at` 这类时间字段在项目里的作用。

06/23 主要复习了 SQL 基础语句，包括 `SELECT`、`INSERT`、`UPDATE`、`DELETE`、`WHERE`、`ORDER BY`、`LIMIT`、`OFFSET`。这天更像是把之前学 Java 后端时接触过的 SQL 重新捡起来。虽然语法不难，但是隔了一段时间不用还是会忘，所以这周后面主要靠实际写接口来重新熟悉。

06/24 开始把 Todo 的创建和查询接入 MySQL。这里学到了 `Exec`、`QueryRow`、`Scan`、`LastInsertId`、`sql.ErrNoRows` 这些用法。`Exec` 更适合执行 `INSERT`、`UPDATE`、`DELETE` 这种写操作；`QueryRow` 适合查单行；`Scan` 则是把数据库查出来的字段填进 Go 变量。这里也意识到真正的错误很多时候不是发生在 `QueryRow` 本身，而是发生在后面的 `Scan`。

06/25 主要把 Todo 的更新、标记完成和删除接口接入 MySQL。这里比较重要的是 `RowsAffected`，它可以判断一次 `UPDATE` 或 `DELETE` 到底影响了多少行。如果影响行数是 0，就说明对应的任务不存在，接口应该返回 404，而不是假装操作成功。

06/26 给 Todo 列表增加了分页和完成状态筛选。分页主要用 `LIMIT ? OFFSET ?`，完成状态筛选则是在 SQL 里根据 `completed` 参数动态加 `WHERE completed = ?`。这里开始感觉到接口设计不只是把代码写出来，还要考虑默认值、参数合法性、排序稳定性和返回结构。

06/27 继续整理 Todo MySQL CRUD，并给列表接口补了更标准的分页响应结构。原来的列表接口只返回任务数组，但是分页接口还需要返回 `page`、`page_size`、`total`、`total_pages` 这些信息，所以又增加了 `COUNT(*)` 查询和新的响应体。当前项目已经上传到 GitHub。

### 项目完成内容

这周在上周 Todo List demo 的基础上继续完善，主要完成了以下内容：

- 使用 MySQL 存储 Todo 数据
- 编写 `schema.sql` 创建数据库和 `todos` 表
- 使用 `database/sql` 连接数据库
- 使用 `go-sql-driver/mysql` 作为 MySQL 驱动
- 将创建任务接口改为写入数据库
- 将查询任务接口改为从数据库读取
- 将更新、标记完成、删除接口接入数据库
- 使用 `RowsAffected` 判断更新或删除是否真的命中数据
- 给列表接口增加分页和完成状态筛选
- 给列表接口增加 `total` 和 `total_pages`
- 前端字段从 `done` 调整为 `completed`

### 接口列表

```text
POST   /api/todos           创建任务
GET    /api/todos           查询任务列表，支持分页和 completed 筛选
PUT    /api/todos/:id       更新任务
PATCH  /api/todos/:id/done  标记完成
DELETE /api/todos/:id       删除任务
```
