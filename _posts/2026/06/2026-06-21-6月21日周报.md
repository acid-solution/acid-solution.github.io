### 每日内容总结

06/15 学了 Go 原生 `net/http`。主要理解了 `http.HandleFunc`、`http.ListenAndServe`、`http.ResponseWriter`、`*http.Request` 这些基础概念。也知道了 HTTP 响应大致由状态码、响应头和响应体组成，返回 JSON 时需要设置 `Content-Type`，并用 `json.NewEncoder(w).Encode(resp)` 把 Go 结构体写入响应。

06/16 开始学 Gin。Gin 的基本流程是创建路由器、注册接口、启动服务。`gin.Context` 可以理解成当前这一次 HTTP 请求的操作工具箱，handler 可以通过它读取请求参数、请求体、Header，也可以用它返回 JSON、设置状态码。这里开始感觉到框架确实比原生 `net/http` 更方便。

06/17 学了参数绑定。GET 请求可以用 `c.Query` 手动取参数，也可以用 `c.ShouldBindQuery(&req)` 自动绑定到结构体。POST JSON 请求可以用 `c.ShouldBindJSON(&req)` 绑定请求体。这里比较重要的是，参数校验失败时要及时返回错误，不应该继续进入业务逻辑。

06/18 学了 JSON 响应和状态码。后端处理完请求后给客户端的回应就是 HTTP Response，它包含状态码和响应体。Gin 里可以用 `c.JSON(status, data)` 返回 JSON。简单场景可以用 `gin.H`，复杂场景更适合定义结构体。状态码大致可以分成 2xx 成功、4xx 客户端错误、5xx 服务端错误。

06/19 学了统一响应结构。HTTP 状态码和业务 code 不完全一样，所以可以用 `code/message/data` 包一层业务响应。这样 handler 里只需要调用 `Success(c, data)` 或 `Fail(c, status, message)`，代码会更干净，也更接近真实后端项目。

06/20 整理了一个 Go + Gin 入门级 Todo List 后端项目。项目里托管了前端静态文件，后端提供 Todo 的创建、查询、更新、标记完成、删除接口，并用内存 map 模拟数据库。最后前后端联调成功，整个请求链路跑通了。

### 接口列表

```text
POST   /api/todos           创建任务
GET    /api/todos           查询任务列表
PUT    /api/todos/:id       更新任务
PATCH  /api/todos/:id/done  标记完成
DELETE /api/todos/:id       删除任务
```

### 请求链路

```text

↓

↓

↓

↓
返回统一 JSON
↓
前端刷新页面
```
