### 每日内容总结

06/29 开始把 Todo 项目接入 GORM。主要是为 Todo 定义 model，并用 GORM 连接 MySQL 和执行 AutoMigrate。这里重新理解了一下 ORM，也就是 Object-Relational Mapping，对象关系映射。AutoMigrate 的优点是开发效率比较高，可以根据 model 自动映射表结构，不过实际生产环境里应该不会这么随意地自动改表。

06/30 用 GORM 改写了 Todo 的 CRUD。这里学到了 `Create`、`First`、`Find`、`Updates`、`Delete` 这些基础操作。比较重要的是，GORM 的 `Create` 可以把数据库生成的主键 ID 和时间戳回填到结构体里，所以传进去的一般是指针。`First` 查一条，`Find` 查多条，`Updates` 可以用 `map[string]any` 更新多个字段。整体看下来，GORM 比手写 SQL 简洁很多，但也更需要理解它背后到底帮我做了什么。

07/01 把 Todo 项目的端口、MySQL DSN 等配置从代码里拆了出来，支持从环境变量读取。本地用 `.env` 保存开发配置，同时用 `.gitignore` 避免把敏感配置提交出去。这里写了一个 `Config` 类型来统一保存配置，感觉项目开始有一点工程结构了，不再是把所有东西都堆在 `main.go` 里。

07/02 给 Todo API 接入了结构化日志和请求日志中间件。这里主要用了 Go 标准库里的 `slog`，并给每一次 HTTP 请求生成一个 `request_id`，放进 Gin 的上下文和响应头里。还理解了中间件其实就是返回一个可以作为 handler 的函数，`c.Next()` 的意思是继续执行后面的中间件和 handler，等后面的逻辑执行完之后再回来。

07/03 整理了参数校验、统一错误码和错误响应。主要是区分参数错误、资源不存在和服务端错误，让接口返回不只是简单的字符串，而是更统一的业务响应结构。这天还因为放假回家，把项目从实验室电脑交接到了自己电脑上，也算是顺手整理了一下工作流。

07/04 做了 Todo API v1 的工程化整理，拆分了 handler、service、repository、model、response、config 等目录。一开始我直接创建了所有文件准备一起改，结果发现要改的地方太多，很容易乱掉，后面又全撤回了。后来改成从不依赖其他函数的文件开始，一个一个改，用编译报错逐渐把引用关系修正，这种方式明显更稳。现在能更清楚地看到依赖方向大概是：handler -> service -> repository -> model。

### 自我感悟

这周的感觉是，后端项目只是“把接口写出来”还是挺简单的，但是代码组织起来后续维护才更方便。之前单文件 demo 写起来很快，但是功能一多就会乱。拆分目录之后，handler、service、repository 各自负责什么会更清楚，虽然代码量上多了很多，也有些冗余，但是其他人或者自己之后维护，找问题都会方便非常多。

分层要考虑的东西也挺多。麻烦的是依赖关系怎么调整，结构体怎么传，错误怎么从底层返回到上层，响应又应该在哪里统一处理。尤其是一次性大改的时候，很容易所有地方都报错，反而不知道从哪里修起。后面这种工程化修改，应该按依赖顺序慢慢来。

### 未弄明白

和上周一样，代码写的不熟练，甚至有些地方读起来都稍微有点困难。还需要多练增加熟练度

### 本周刷题收获

1. 有效的括号是比较典型的栈题，左括号压栈，右括号弹栈，弹不出就报错退出。要注意的是go没有官方的栈这个数据结构，需要用切片自己模拟栈
2. 螺旋矩阵和旋转图像都属于矩阵题。矩阵题本身算法不一定复杂，但下标和边界很容易写错。螺旋矩阵要维护上下左右边界，旋转图像则可以从“先转置再反转每一行”这个角度来想。
3. 买卖股票的最佳时机，遍历用的i是什么意义，需要思考。前面买入，后面卖出，遍历的i应该用卖出的意义。然后倒退最好情况下的买入，即可得到思路。
4. 爬楼梯本质上是斐波那契型动态规划，只需要维护前两个状态就可以，不需要开完整数组。本题dp需要考虑最后一步是走几步，想通了就能得到转移方程
5. 这周中等题主要还是卡在矩阵边界和原地操作上，之后遇到这类题不能急着写，最好先在纸上把一圈或者一次交换的过程画清楚。

### 接口列表

```text
POST   /api/todos           创建任务
GET    /api/todos           查询任务列表，支持分页和 completed 筛选
PUT    /api/todos/:id       更新任务
PATCH  /api/todos/:id/done  标记完成
DELETE /api/todos/:id       删除任务
```

### 请求链路

```text
前端点击按钮
↓
发送 HTTP 请求
↓
Gin 路由匹配
↓
request_id 中间件生成请求 ID
↓
请求日志中间件记录方法、路径、状态码和耗时
↓
Handler 绑定和校验请求参数
↓
Service 处理业务逻辑
↓
Repository 使用 GORM 操作 MySQL
↓
Model 映射数据库表结构
↓
Response 组装统一 JSON
↓
前端刷新页面
```

### 项目收获

这周 Todo 项目最大的变化是从“功能能跑”开始走向“结构能看”。之前虽然已经接入了 MySQL，但是很多逻辑还是比较直接地写在一起。现在拆出 handler、service、repository 之后，请求从路由进来之后怎么一层层往下走，会更清楚一些。
